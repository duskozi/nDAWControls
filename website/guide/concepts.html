Core concepts

The ideas that are the same in every control: value controls, tapers, value text, colours, models and drawing.

#Value controls

Knob, Fader and ValueBox derive from DawRangeControl, which derives from WPF's RangeBase. So Minimum, Maximum, Value, SmallChange, LargeChange and the ValueChanged event work exactly as in a Slider. On top of that they share these properties:

PropertyWhat it does
DefaultValueValue after a double-click, Ctrl+click or the Delete key. Also where a bipolar knob's ring starts.
TaperThe curve between the value and the control position: Linear, Log or Decibel.
StepSnaps user changes to multiples, for example 1 for whole numbers. 0 = continuous.
LabelThe parameter name shown with the control.
ValueFormatterA Func<double, string> that makes the value text.
ValueStringFormatOr a composite format string, for example {}{0:0.0} dB.
MinimumTextText shown at the minimum, for example -∞ or Off.
DragSensitivityPixels of mouse travel for the full range (200 by default).
FineFactorSpeed while Shift is held (0.1 by default).
IsDraggingTrue while the user holds the control (read-only).

Two routed events, DragStarted and DragCompleted, mark the start and end of a mouse gesture. Use them for automation "touch" and to make one drag one undo step. ResetToDefault() and SetNormalizedValue(0..1) are handy from code.

#Tapers

The taper decides how the position of a knob or fader maps to its value. In XAML you write the name; in code use ValueTaper.Linear, ValueTaper.Logarithmic or ValueTaper.Decibel.

XAMLUse forBehaviour
LinearMost parameters, pan, mixEqual travel, equal change
LogFrequencies, timesEvery octave gets the same travel. Needs a positive minimum.
DecibelVolume fadersThe mixer curve: room around 0 dB, the bottom compressed to -∞
XAML
<daw:Knob  Label="Freq"  Taper="Log"     Minimum="20"  Maximum="20000"/>
<daw:Fader Height="200"  Taper="Decibel" Minimum="-60" Maximum="6"/>

You can also write your own: derive from ValueTaper and implement the mapping between value and a normalized 0..1 position.

#Value text

The text under a knob or fader comes from ValueFormatter if set, else from ValueStringFormat, and MinimumText wins at the minimum. ValueFormatters has ready-made formatters for XAML:

FormatterExample output
ValueFormatters.Decibel-6.0 dB, -∞
ValueFormatters.PanL30, C, R100
ValueFormatters.Percent80%
ValueFormatters.Frequency440 Hz, 1.2 kHz
ValueFormatters.Time20 ms, 1.5 s
ValueFormatters.Tempo120.0 BPM
ValueFormatters.Integer12
XAML
<daw:Knob Label="Cutoff" ValueFormatter="{x:Static daw:ValueFormatters.Frequency}"/>
C#
knob.ValueFormatter = v => v < 0.5 ? "Soft" : "Hard";

#Colours and brushes

The controls are lookless: every colour is a brush property, and the default style sets it from the active skin with DynamicResource. That gives you three levels of control:

  1. Switch the skin to change everything (Skins).
  2. Override a skin key in your own resources to change one colour everywhere, for example the accent.
  3. Set a brush property on one control to change only that control, for example ArcBrush on one knob or TrackColor on a channel strip.
XAML
<!-- only this knob is purple -->
<daw:Knob Label="Mix" ArcBrush="#FFB18CFF"/>

<!-- every LED meter in this panel switches to orange earlier -->
<daw:LevelMeter WarningDb="-18" DangerDb="-6" WarningBrush="Orange"/>

Each control page lists its colour properties under API reference.

#Models

The note editors work on small model classes from nDAWControls.Models. All of them use beats (quarter notes) for time, so they are independent of tempo and PPQ.

ClassUsed byWhat it holds
MidiNotePianoRoll, ControllerLane (velocity)Pitch (0..127), Start and Length in beats, Velocity (1..127), IsSelected, optional Brush. Implements INotifyPropertyChanged.
ControllerPointControllerLanePosition in beats and Value (0..127, or -8192..8191 for pitch bend).
StepPatternStepSequencerA rows × steps grid of velocities (0 = off) with GetVelocity, SetVelocity, IsOn, Clear and a StepChanged event.
KeyHighlightPianoKeyboard.SetStateA lit key: note, colour, intensity, and optional hand and finger.
C#
using nDAWControls.Models;

var notes = new ObservableCollection<MidiNote>
{
    new(pitch: 60, start: 0, length: 1, velocity: 100),
    new(64, 1, 1),
};
var points  = new ObservableCollection<ControllerPoint> { new(0, 0), new(4, 127) };
var pattern = new StepPattern(rows: 4, steps: 16);

Converting from MIDI ticks: beats = ticks / (double)ticksPerQuarterNote.

#Focus and keyboard

Every interactive control can take keyboard focus and shows the skin's focus outline. Knobs, faders and value boxes use the arrow keys, Page Up/Down and Home/End; the piano roll, step sequencer and keyboard have their own keys, listed on their pages. Use IsTabStop and TabIndex as with any WPF control.

#Drawing and performance

Frames, LEDs, caps and note bodies are drawn by a native nine-patch renderer (NinePatchLib.dll, from the NinePatch.Core package) at the exact device-pixel size, and cached. A hundred equal buttons share one bitmap. The cache follows the skin and the DPI, so a skin change or a move to another monitor redraws everything sharply.

Without the native renderer (32-bit or ARM64 processes, or a PC without the Visual C++ runtime) the controls draw the same frames as vectors. Nothing breaks, it is only a little slower.

Big controls only draw what is visible: the piano roll draws the visible notes, and meters and activity lights draw at most once per frame. Collapsed controls (for example in a hidden DawPanel) draw nothing at all.

i
For the fastest drawing, build your app for x64 (<PlatformTarget>x64</PlatformTarget> or <RuntimeIdentifier>win-x64</RuntimeIdentifier>).
