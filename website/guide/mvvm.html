MVVM and binding

The controls are ordinary WPF controls with dependency properties, routed events and commands, so they fit any MVVM setup.

#Binding values

Bind value properties two-way. Value of Knob, Fader and ValueBox binds two-way by default (it comes from RangeBase); for the others write Mode=TwoWay to be safe:

XAML
<daw:Knob Label="Cutoff" Value="{Binding Cutoff}"/>
<daw:XYPad XValue="{Binding X, Mode=TwoWay}" YValue="{Binding Y, Mode=TwoWay}"/>
<daw:ChannelStrip Volume="{Binding Volume, Mode=TwoWay}" IsMuted="{Binding IsMuted, Mode=TwoWay}"/>
<daw:EnvelopeEditor Attack="{Binding Attack, Mode=TwoWay}" Sustain="{Binding Sustain, Mode=TwoWay}"/>

A minimal view-model base, used in the examples on this site (or use CommunityToolkit.Mvvm's ObservableObject):

C#
using System.ComponentModel;
using System.Runtime.CompilerServices;

public abstract class ObservableObject : INotifyPropertyChanged
{
    public event PropertyChangedEventHandler? PropertyChanged;

    protected bool Set<T>(ref T field, T value, [CallerMemberName] string? name = null)
    {
        if (EqualityComparer<T>.Default.Equals(field, value)) return false;
        field = value;
        PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
        return true;
    }
}

public sealed class SynthViewModel : ObservableObject
{
    private double _cutoff = 1200, _resonance = 0.2;
    public double Cutoff    { get => _cutoff;    set { if (Set(ref _cutoff, value)) Engine.SetCutoff(value); } }
    public double Resonance { get => _resonance; set { if (Set(ref _resonance, value)) Engine.SetResonance(value); } }
}

#Commands

TransportBar exposes PlayCommand, StopCommand, RecordCommand, RewindCommand, ForwardCommand and ToStartCommand. PlayCommand and RecordCommand receive the new on/off state as their parameter. LedToggleButton and TransportButton are toggle buttons, so Command and IsChecked work as usual.

XAML
<daw:TransportBar IsPlaying="{Binding IsPlaying, Mode=TwoWay}" Tempo="{Binding Tempo, Mode=TwoWay}"
                  PlayCommand="{Binding PlayCommand}" StopCommand="{Binding StopCommand}"/>
C#
// With CommunityToolkit.Mvvm
public IRelayCommand<bool> PlayCommand => new RelayCommand<bool>(play => { if (play) Engine.Play(); else Engine.Pause(); });
public IRelayCommand StopCommand => new RelayCommand(() => { Engine.Stop(); Position = 0; });

#Collections

PianoRoll.Notes takes any IList<MidiNote>; use an ObservableCollection<MidiNote> so additions and removals from your view-model show at once. Each MidiNote raises PropertyChanged, so changing a note's pitch or velocity in code redraws it too. The same goes for ControllerLane.Points.

XAML
<daw:PianoRoll Notes="{Binding Notes}" PlayheadPosition="{Binding Position, Mode=TwoWay}"/>

#Undo

Value controls and the XY pad and envelope raise DragStarted and DragCompleted; the piano roll raises NotesEdited and the controller lane LaneEdited once per finished gesture. Those are the moments to record undo steps, so a drag is one step and not hundreds.

C#
// A tiny snapshot-based undo for a piano roll
private readonly Stack<MidiNote[]> _undo = new();

roll.NotesEdited += (s, e) => _undo.Push(notes.Select(n => n.Clone()).ToArray());

void Undo()
{
    if (_undo.Count < 2) return;
    _undo.Pop();                                   // the current state
    var previous = _undo.Peek();
    notes.Clear();
    foreach (var n in previous) notes.Add(n.Clone());
}

#Events in XAML or code

Routed events (DragStarted, NoteOn, NotesEdited, PedalChanged …) can be handled in XAML, in code-behind, or with an event-to-command behavior (Microsoft.Xaml.Behaviors.Wpf) if you keep code-behind empty.

XAML
<daw:PianoKeyboard NoteOn="OnKeyNoteOn" NoteOff="OnKeyNoteOff"/>
